# 投研报告评估

把"这份报告可不可信"变成可测量的数字,支撑「改模板 → 重新评估 → 对比」的迭代循环。

## 三层指标

| 层 | 指标 | 怎么算 | 需要模型 |
|---|---|---|---|
| 溯源 | 链接有效率 / 链接命中率 / 数字覆盖率 | 正则 + 集合运算 | 否 |
| 幻觉 | 幻觉率 / 无据率 | 逐条断言判定 | 是 |
| 完整性 | 维度覆盖清单 | 人工对照券商研报 | — |

**只看链接有效率会被"假溯源"骗过去**:实测有一份报告 24 个链接全部指向发布商
首页,报告自己也承认这是占位;它在有效率上是满分,在命中率上是零分。

## 用法

```bash
# 1. 跑研究并落证据快照(报告 + 全部原文 + 带来源的上下文块)
venv/bin/python -m evals.investment_eval.run_research

# 2. 溯源率(秒级,零成本)
venv/bin/python -m evals.investment_eval.report

# 3. 幻觉率
venv/bin/python -m evals.investment_eval.hallucination_report

# 4. 判定准确率验证与选型
venv/bin/python -m evals.investment_eval.validation.run
```

凭据:第 1 步走主流程的 `ZHIPUAI_API_KEY` + `TAVILY_API_KEY`;第 3、4 步走
`DEEPSEEK_API_KEY` —— 判定模型必须与写作模型不同厂,所以这两条链路刻意分开。
第 2 步是纯正则,不调任何模型。

## 为什么要落快照

`outputs/task_*.json` 只有报告正文和事件日志,没有任何一条原文。核对一个数字
需要"当时看到的那份原文",而不是"现在重新访问那个 URL 拿到的内容" —— 网页会
改会挂,改了就分不清是模型编的还是网页变了。

上游 `evals/hallucination_eval` 是同进程内存里跑完就地评估、用完即弃,无法离线
重评、无法换模型重跑、无法在改了模板之后做前后对比。

## 判定为什么可信

1. **强制抄写原文并用代码核验**。判定模型必须把依据的那句原文原样抄出来,本模块
   用字符匹配去核对;抄不出来就不许判"有支撑",降级为"查无此据"。模型可以
   "觉得"原文支持,但没法凭空抄出一句原文里不存在的话而不被发现。

2. **判定模型与写手不同源**。同源模型对自己的输出有系统性偏袒 —— 它编错的地方
   正是它认为对的地方。本项目写手是智谱 GLM,判定一律用别家(当前 DeepSeek),
   代码里有硬校验(`judge.py` 的 `FORBIDDEN_JUDGE_SUBSTR`)。换写作模型时必须
   同步改这条禁令,否则会退化成模型给自己打分。

3. **准确率有实测**。`validation/` 从真实卷宗构造已知答案的题目(原样抄 /
   改数字 / 编造指标),不需人工标注即可得出准确率。

4. **判定调用失败与"查无此据"分开统计**。两者都返回 `NOT_FOUND`,但一个是工具
   故障、一个是真实结论。混在一起时,一次账户欠费会伪装成"无据率 90%"(实测
   71 条里 62 条判定失败)。失败条目不进分母、不落检查点(否则续跑会把它们当成
   已判定结果沿用),并在看板上显式告警。

## 模型选择

| 用途 | 模型 | 依据 |
|---|---|---|
| 断言抽取 | `deepseek-v4-flash`(关闭思考) | 同一 2053 字符分块:关思考 4.0s,原样 >190s 超时 |
| 判定 | `deepseek-v4-flash` | 76 题验证集 97%,59s,抄写降级 0 |

判定候选的完整对照(同一验证集):

| 模型 | 准确率 | 耗时 | 抄写降级 |
|---|---|---|---|
| `deepseek-v4-flash` | **97%** (74/76) | **59s** | **0** |
| `deepseek-v4-pro` | 96% (73/76) | 146s | 3 |
| `Qwen/Qwen3.6-35B-A3B` | 96% | 82s | — |
| `zai-org/GLM-5.2` | 99% | 629s | — |
| `Qwen/Qwen3-30B-A3B-Instruct-2507` | 76% | 31s | — |

pro 在这个任务上没有优势:更慢,抄写核验反而多失败 3 次。判定不是开放推理,是
受限任务 —— 给定断言和几段原文,判支持/矛盾/找不到,并逐字抄回佐证句(代码校验)。
吃的是指令遵循,不是推理深度。

**抽取那一行是一次错误归因的修正。** 上一版把模型定成 `Qwen3-30B-A3B-Instruct`,
结论写成"DeepSeek 慢、Qwen 快",按厂商归因。真正的变量是模型名里的 `Instruct`
(非思考变体)—— 思考型模型在出结果前烧掉大量隐藏推理 token,而抽取是机械拆句,
推理没有收益。换厂商时因此又踩了同一个坑,直到 GLM 也超时才排除掉厂商这个假设。

## 已知局限

- **合成验证集给的是准确率上限,不是保证。** 构造的题比真实情况干净 —— 数字改动
  明显、编造的指标离谱;真实报告里的难题是单位换算、口径不同、时间错配,这套题
  测不到。人工抽样标注仍然值得做,只是不必作为前置条件。
- **只判数字型断言。** 定性判断("护城河稳固")的核对一致性差,同一句判两次结论
  会变,拿它算出来的幻觉率没有意义。
- **抽取器会把对比基期挂到当期主语上。** 报告写 "FQ3 revenue was $41.46B, versus
  $23.86B the prior quarter",抽取器可能拆出 "FQ3 revenue was $23.86B in the prior
  quarter" —— 读起来是对当期的断言,于是被正确判成矛盾,但报告本身没错。提示里已加
  规则和反面示例,残余假阳性仍需人工复核"矛盾"清单。这也是看板默认打印矛盾明细的
  原因:这个指标不适合无人值守地只看比率。
