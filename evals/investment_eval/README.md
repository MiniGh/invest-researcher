# 投研报告评估

把"这份报告可不可信"变成可测量的数字,支撑「改模板 → 重新评估 → 对比」的迭代循环。

## 三层指标

| 层 | 指标 | 怎么算 | 需要模型 |
|---|---|---|---|
| 溯源 | 链接有效率 / 链接命中率 / 数字覆盖率 | 正则 + 集合运算 | 否 |
| 幻觉 | 幻觉率 / 无据率 | 逐条断言判定 | 是 |
| 完整性 | 维度覆盖清单 | 人工对照券商研报 | — |

**只看链接有效率会被"假溯源"骗过去**:实测有一份报告 24 个链接全部指向发布商
首页,报告自己也承认这是占位;它在有效率上是满分,在命中率上是零分。

## 用法

```bash
# 1. 跑研究并落证据快照(报告 + 全部原文 + 带来源的上下文块)
venv/bin/python -m evals.investment_eval.run_research

# 2. 溯源率(秒级,零成本)
venv/bin/python -m evals.investment_eval.report

# 3. 幻觉率
venv/bin/python -m evals.investment_eval.hallucination_report

# 4. 判定准确率验证与选型
venv/bin/python -m evals.investment_eval.validation.run
```

## 为什么要落快照

`outputs/task_*.json` 只有报告正文和事件日志,没有任何一条原文。核对一个数字
需要"当时看到的那份原文",而不是"现在重新访问那个 URL 拿到的内容" —— 网页会
改会挂,改了就分不清是模型编的还是网页变了。

上游 `evals/hallucination_eval` 是同进程内存里跑完就地评估、用完即弃,无法离线
重评、无法换模型重跑、无法在改了模板之后做前后对比。

## 判定为什么可信

1. **强制抄写原文并用代码核验**。判定模型必须把依据的那句原文原样抄出来,本模块
   用字符匹配去核对;抄不出来就不许判"有支撑",降级为"查无此据"。模型可以
   "觉得"原文支持,但没法凭空抄出一句原文里不存在的话而不被发现。

2. **判定模型与写手不同源**。同源模型对自己的输出有系统性偏袒 —— 它编错的地方
   正是它认为对的地方。本项目写手是 DeepSeek,判定一律用别家,代码里有硬校验。

3. **准确率有实测**。`validation/` 从真实卷宗构造已知答案的题目(原样抄 /
   改数字 / 编造指标),不需人工标注即可得出准确率。

## 模型选择

| 用途 | 模型 | 依据 |
|---|---|---|
| 断言抽取 | `Qwen/Qwen3-30B-A3B-Instruct-2507` | 同一分块 15.7s;DeepSeek-V4-Flash 175s 超时 |
| 判定(默认) | `Qwen/Qwen3.6-35B-A3B` | 验证集 96%,425 条约 8 分钟 |
| 判定(高置信) | `zai-org/GLM-5.2` | 验证集 99%,但慢 7.7 倍 |

## 已知局限

- **合成验证集给的是准确率上限,不是保证。** 构造的题比真实情况干净 —— 数字改动
  明显、编造的指标离谱;真实报告里的难题是单位换算、口径不同、时间错配,这套题
  测不到。人工抽样标注仍然值得做,只是不必作为前置条件。
- **只判数字型断言。** 定性判断("护城河稳固")的核对一致性差,同一句判两次结论
  会变,拿它算出来的幻觉率没有意义。
- **卷宗偏薄。** 当前资料几乎全部来自搜索接口返回的摘要而非抓取正文,平均每篇约
  一千字。原文越短,"查无此据"越容易偏高 —— 那可能只是摘要里没写,不是模型编的。
